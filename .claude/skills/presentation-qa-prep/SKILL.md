# 발표 질의응답 준비

발표를 앞둔 사람이 "어떤 질문이 나올지, 뭐라고 답할지"를 미리 준비하도록 돕는 스킬이다. 핵심은 질문이 발표 슬라이드 재탕이 아니라, 슬라이드 바깥의 자료(논문·기사)와 부딪히거나 보완되는 지점에서 나와야 한다는 것 — 그래야 실제 질의응답에서 나올 법한 날카로운 질문이 된다.

입력은 보통 PDF/PPT 파일이지만, 사용자가 발표 내용을 텍스트로 붙여넣는 경우도 똑같은 절차로 처리한다.

## 절차

### 1단계. 발표 내용 정리
파일을 읽고(PDF는 pymupdf 또는 기본 PDF 리더로) 슬라이드/섹션 단위로 핵심 내용을 정리한다. 전체를 옮겨 적는 요약이 아니라, 이후 질문을 만들 때 "몇 쪽에서 무슨 주장을 했는지" 바로 찾아볼 수 있는 수준으로 정리한다. 가능하면 슬라이드 번호나 쪽 번호를 같이 적어 둔다 — 3단계의 질문에서 이 번호를 인용한다.

### 2단계. 낯선 용어 설명
정리하면서 발표를 처음 보는 사람에게는 낯설 수 있는 용어·개념·약어를 추려 뜻을 설명한다. 이 단계를 건너뛰면 질문 자체가 용어를 잘못 이해한 채로 만들어질 수 있으므로, 질문을 쓰기 전에 반드시 먼저 끝낸다.

### 3단계. 질문 만들기 — 형식 고정
이 스킬에서 가장 중요한 부분이다. 질문 하나하나를 아래 세 줄 형식으로 쓴다. 이 순서와 구성 요소를 빠뜨리면 질문을 다시 쓴다.

```
**발표 내용**: [몇 쪽/몇 번째 슬라이드에서 무엇을 다뤘는지 1~2문장]
**근거**: [외부 논문·기사 제목, 저자 또는 매체, 발행연도, 출처(URL 등)] — 이 자료가 왜 이 질문으로 이어지는지 한 줄
**질문**: "실제로 묻는 문장"
```

근거를 만드는 방법:
- 반드시 WebSearch(필요하면 WebFetch로 원문 확인)로 실제 자료를 찾는다. 근거를 지어내거나 기억에 의존해 쓰지 않는다 — 발표자가 재질문에서 "그 자료 어디서 보신 거예요"라고 물으면 바로 막히기 때문이다.
- 검색어는 발표에서 정리한 핵심 주장·수치·용어를 그대로 써 본다. 한국어 자료가 빈약하면 영어로도 검색한다.
- 찾은 자료가 발표 내용과 같은 방향(보강)이든 다른 방향(반박·다른 수치·다른 결론)이든 상관없다. 둘 다 좋은 질문이 된다. 다만 검색해서 적절한 근거를 못 찾은 주제는 질문으로 쓰지 말고 버린다 — 근거 없는 질문은 이 스킬의 결과물이 아니다.
- 질문 개수는 사용자가 정하지 않으면 4~6개로 한다. 발표의 여러 섹션에 고르게 걸치도록 고른다(한 슬라이드에서만 질문을 뽑지 않는다).

### 4단계. 예상 답변과 꼬리질문
질문마다 아래 두 줄을 덧붙인다.

```
**예상 답변**: [발표 자료 내용을 근거로, 발표자가 실제로 할 법한 답변]
**재질문**: "예상 답변의 허점·생략된 부분·일반화를 파고드는 꼬리질문"
```

예상 답변은 발표 자료에 있는 내용으로 채운다. 발표 자료에 답이 없는 질문이면 "발표 자료에 근거가 없어 이렇게 답할 가능성이 높다"는 식으로 추론임을 밝힌다. 재질문은 그 예상 답변을 그대로 받아들이지 않는 사람의 입장에서, 한 걸음 더 들어가는 질문이어야 한다 — 예상 답변을 그냥 되풀이하는 질문은 쓰지 않는다.

## 출력

- 입력 파일과 같은 폴더에 `<원본 파일명> 질의응답준비_YYYYMMDD_HHmm.md`로 저장한다(타임스탬프는 현재 날짜·시간). 같은 발표로 여러 번 돌릴 때마다 새 파일이 생기므로 이전 준비 내용이 덮어써지지 않는다.
- 구성 순서: (1) 발표 내용 정리 (2) 용어 설명 (3) 질문 블록들(3·4단계 다섯 줄 형식을 질문마다 반복).
- 저장한 뒤 전체 내용을 채팅에도 그대로 보여준다. 저장 경로를 한 줄로 알려준다.
